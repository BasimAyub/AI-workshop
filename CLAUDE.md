# Project Overview

BookShelf is a personal book catalogue. Users browse, search, add, and delete books persisted in root `/data/*.json` files. It is an npm workspaces monorepo: Express API, React frontend, and a shared types package.

# Architecture

- `/apps/api/src/routes/books.ts` — route handlers only; no business logic
- `/apps/api/src/services/bookService.ts` — all filtering, pagination, and write logic
- `/apps/api/src/data/fileStore.ts` — sole entry point for reading/writing JSON files
- `/apps/api/src/middleware/validation.ts` — `validateBook` middleware for POST body validation
- `/apps/api/src/middleware/errorHandler.ts` — `ApiError` class, `errorHandler`, `notFoundHandler`
- `/apps/web/src/` — React/Vite/Tailwind frontend
- `/packages/shared/src/types.ts` — `Book`, `Shelf`, `Review`, `BookWithReviews` interfaces
- `/data/books.json`, `/data/shelves.json`, `/data/reviews.json` — active data (root-level)

# API Rules

Route handlers call service methods and return the result. Business logic (filtering, slicing, ID generation) belongs in `bookService.ts`.

**Response shapes:**

- Paginated list (`GET /api/books`, `GET /api/books/search`): `{ data: Book[], total, page, totalPages }`
- Single book (`GET /api/books/:id`): returns `BookWithReviews` object directly (no wrapper)
- Created book (`POST /api/books`): returns the new `Book` object directly, status `201`
- Deleted book (`DELETE /api/books/:id`): returns the deleted `Book` object directly
- All errors: `{ error: { status, message } }` — validation errors add a `details: string[]` field

**Status codes:** `200` (GET success), `201` (POST success), `400` (bad input), `404` (not found), `500` (write failure).

`notFoundHandler` must be registered before `errorHandler` in `index.ts`.

# Data Layer Rules

Read and write JSON exclusively via `bookStore`, `shelfStore`, and `reviewStore` in `/apps/api/src/data/fileStore.ts`. Never call `fs` or import JSON directly from routes or services.

Active data lives at root `/data/`, not `/apps/api/data/`. The file `/apps/api/data/books.json` is a stale development artifact; ignore it.

IDs are generated by `generateId(prefix)` in `fileStore.ts` — format is `${prefix}_<timestamp36><random>` (e.g. `book_mpv2br89vfs5bj`). Never use sequential IDs like `book_001`.

`shelfStore` and `reviewStore` exist in `fileStore.ts` but no API routes for shelves or reviews have been built yet.

# Validation and Error Handling

`validateBook` middleware runs before `POST /api/books` and handles all body validation. Do not duplicate this logic in the route or service.

Rules for `POST /api/books`:

- `title`: required, non-empty after trim, max 200 characters
- `author`: required, non-empty after trim
- `genre`: required, non-empty after trim
- `year`: required, integer between 1000 and the current year (inclusive)
- `isbn`, `description`: optional; if present, must be strings. Stored as empty string when omitted.

Middleware trims all string fields before they reach the route handler.

`ApiError(status, message)` is the mechanism for service-layer errors. `errorHandler` serialises it to `{ error: { status, message } }`. It also catches `entity.parse.failed` Express errors and returns `400` with `"Invalid JSON in request body"` — do not re-implement this elsewhere.

# Testing Rules

Tests live in `/apps/api/tests/`. The Jest config uses `ts-jest` with commonjs interop.

Mock `bookService` at the module level with `jest.mock('../src/services/bookService')`. Do not mock `fileStore` directly in route tests.

Never read from or write to `/data/*.json` in any test. Use inline fixture objects only.

For each new endpoint, cover: success case, each validation/input error, 404 not found, and 500 write failure (where the service can throw).

`GET /api/health` and `GET /api/books` suites in `books.test.ts` are empty placeholder `describe` blocks. Replace them with real assertions when those endpoints are touched.

`DELETE /api/books/:id` is implemented but has no tests.

# What NOT to do

- Do not add PostgreSQL, MongoDB, Prisma, TypeORM, Sequelize, or any database.
- Do not add authentication, sessions, or user management.
- Do not read or write JSON files outside of `/apps/api/src/data/fileStore.ts`.
- Do not change the paginated or error response shape unless explicitly instructed.
- Do not add npm dependencies without explicit instruction.
- Do not expose `err.stack` or raw Express parser error messages in API responses.
- Do not add shelf or review API routes unless explicitly asked.
- Do not use sequential IDs (`book_001`); always use `generateId()`.
- Do not change the middleware registration order: `express.json()` → routes → `notFoundHandler` → `errorHandler`.

# Current State / Known Issues

- All six book endpoints are implemented: `GET /api/books`, `GET /api/books/search`, `GET /api/books/:id`, `POST /api/books`, `DELETE /api/books/:id`, `GET /api/health`.
- `GET /api/health` and `GET /api/books` test suites are placeholder stubs with no assertions.
- `DELETE /api/books/:id` has no tests.
- No routes exist for shelves or reviews (types and data files are present).
- `coverUrl` is always `null`; no image upload or lookup is wired up.
- The React frontend supports browse, search, and pagination but has no create or delete UI.
